## 1. Executive Findings

1. **Dataset Misrepresentation & Microscopic Volume:**  
   The primary dataset file [`training/data/hindi_santali_large_parallel.csv`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/training/data/hindi_santali_large_parallel.csv) contains only **202 rows** (101 unique Hindi-Santali translation pairs mirrored bidirectionally). Despite explicit claims in the training script header of integrating AI4Bharat BPCC, Meta FLORES-200, Tatoeba, and JCERT corpora, **zero external corpus records were downloaded or loaded**. The dataset consists purely of 61 hand-written phrases and 40 synthetically combined phrases.

2. **Severe Synthetic Grammatical Corruption (31.7% of Dataset):**  
   Of the 101 unique pairs, 40 pairs (39.6%) were synthetically generated via a naive Python string-combination loop (`subjects` $\times$ `actions`). Because the action predicates were hardcoded in the first-person singular present (*"किताब पढ़ता हूँ"* / *"ᱯᱩᱛᱷᱤᱧ ᱯᱟᱲᱦᱟᱣ ᱠᱟᱱᱟ"*), **32 of the 40 generated pairs (31.7% of the unique dataset) are gross grammatical errors in both languages** (e.g., Hindi: *"तुम किताब पढ़ता हूँ"*, *"वे दौड़ता हूँ"*; Santali: *"ᱟᱢ ᱯᱩᱛᱷᱤᱧ ᱯᱟᱲᱦᱟᱣ ᱠᱟᱱᱟ"* [subject 2nd person *am* + 1st person clitic *-ñ*], *"ᱩᱱᱠᱩ ᱤᱧ ᱫᱟᱹᱲ ᱮᱫᱟ"* [subject 3rd person plural *unku* + 1st person pronoun *iñ*]).

3. **Orthographic Non-Conformance — Absence of Ol Chiki Ohod (`ᱼ` U+1C7E):**  
   The dataset contains **0 instances** of the standard Ol Chiki Ohod character (`ᱼ` U+1C7E), which is required to mark the release of checked consonants before vowels (e.g., `ᱦᱩᱭᱩᱜᱼᱟ`, `ᱮᱱᱮᱡᱼᱟ`, `ᱨᱚᱲᱼᱟ`). Instead, the dataset substitutes an ASCII hyphen (`-` U+002D) across **30 verbal and clitic occurrences** (`ᱦᱩᱭᱩᱜ-ᱟ`, `ᱮᱱᱮᱡ-ᱟ`, `ᱫᱟᱜ-ᱤᱧ`). This breaks standard Ol Chiki Unicode orthography and guarantees tokenization and character n-gram mismatches against standard evaluation corpora (FLORES-200, IN22, BPCC).

4. **Architectural Flaw — Encoder-Only Sequence Tagging Pseudo-Translation:**  
   The custom PyTorch `DualDirectionNMTTransformer` in [`training/download_and_train_large_dataset.py`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/training/download_and_train_large_dataset.py#L177-L198) (787,547 parameters) is **not a sequence-to-sequence translation model**. It is an encoder-only classifier with no decoder, no causal masking, no cross-attention, and no autoregressive generation loop. It trains position $i$ of the source input directly against position $i$ of the target sequence via `CrossEntropyLoss`, treating translation as a 1-to-1 token classification / sequence-labeling task. It is structurally incapable of translating sentences of differing lengths or word orders.

5. **Android Runtime Disconnect & Tokenizer Mismatch:**  
   The trained ONNX model (`santali_nmt_micro_int8.onnx`) is **completely absent from the Android application assets** (`app/src/main/assets/models/` does not exist in the repository). The Android application runs entirely on dictionary lookups and rule-based fallbacks. Furthermore, [`SentencePieceTokenizer.kt`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/app/src/main/java/com/alchemists/tribetalk/translation/SentencePieceTokenizer.kt) hardcodes token IDs starting at 100 with special IDs (`__hin_Deva__` = 256057), which have zero mathematical or index alignment with the token vocabulary generated by the Python training script.

6. **Desktop vs. Mobile Benchmark Mismatch (1.82 GB RAM vs. < 400 MB Budget):**  
   The translation benchmark reported in [`translation/docs/INDICTRANS2_HINDI_SANTALI_EVALUATION.md`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/translation/docs/INDICTRANS2_HINDI_SANTALI_EVALUATION.md) (31.54 chrF++, 4.99 BLEU, 849.93 ms latency) evaluated the 320M-parameter official `IndicTrans2` model on a **Windows 11 desktop workstation** with an Intel/AMD CPU and 16 GB DDR4 RAM on 1,503 IN22-Conv sentences. The benchmark process consumed **1,822.95 MB (1.82 GB) of RAM**. This model was never executed on Android and would immediately trigger an Out-Of-Memory (OOM) crash on target 2 GB RAM Android tablets.

7. **Zero Validation Split and Non-Existent FLN Test Suite:**  
   The training pipeline operates with a **0% validation split** (all 202 rows are trained simultaneously with 100% data leakage across forward and backward directions). Additionally, the "FLN pedagogical test suite with BLEU > 28" cited in system architecture specifications does not exist; [`translation/data/README.md`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/translation/data/README.md#L16-L20) explicitly confirms that the FLN curriculum test set is a placeholder / future scope item.

## 5. Data Quality Issues

### Summary of Major Defects

1. **Systemic Subject-Verb Agreement Failure in Synthetic Data:**  
   The template generator combined 5 subjects (`"मैं"`, `"तुम"`, `"हम"`, `"वह"`, `"वे"`) with 8 actions defined in the 1st person singular. In Hindi, verbs must agree in gender, number, and person. In Santali, pronominal subject clitics (`-ᱧ` for 1st person, `-ᱢ` for 2nd person, `-ᱭ` for 3rd person singular, `-ᱠᱚ` for 3rd person plural) must attach to the verb or preceding constituent. The naive concatenation broke grammatical rules across 32 pairs.
2. **Punctuation Omission & Inconsistency:**  
   Only 4 pairs contain punctuation (`?`). Zero pairs contain the Hindi purna viram (`।`) or Santali mucạd (`᱾`). The remaining 97 pairs have no terminal punctuation.
3. **Orthographic Substitution of ASCII Hyphen for Ol Chiki Ohod:**  
   Standard Ol Chiki uses the Ohod (`ᱼ` U+1C7E) to indicate that an unreleased checked consonant becomes voiced/released when followed by a vowel suffix. The dataset uses the ASCII hyphen (`-`), rendering the text non-compliant with Unicode Ol Chiki standards.
4. **Script Mixing in Android FLN Database:**  
   In [`app/src/main/java/com/alchemists/tribetalk/translation/FLNCurriculumDatabase.kt`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/app/src/main/java/com/alchemists/tribetalk/translation/FLNCurriculumDatabase.kt#L76), item 6 contains mixed English Latin text within the Ol Chiki string: `santaliOlChiki = "ᱤᱧ ᱵᱮ Bes ᱢᱮᱱᱟᱹᱧᱟ"`.

### Critical Architectural Analysis: The Sequence-Labeling Fallacy

The model architecture in `download_and_train_large_dataset.py` is defined as follows:

```python
# Lines 177-198 of download_and_train_large_dataset.py
class DualDirectionNMTTransformer(nn.Module):
    def __init__(self, vocab_size, d_model=160, nhead=4, num_layers=3, dim_ff=384):
        super().__init__()
        self.d_model = d_model
        self.embedding = nn.Embedding(vocab_size, d_model, padding_idx=PAD_ID)
        self.pos_encoder = nn.Parameter(torch.randn(1, 32, d_model) * 0.02)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=dim_ff,
            batch_first=True, activation="gelu"
        )
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)
        self.fc_out = nn.Linear(d_model, vocab_size)

    def forward(self, src_ids):
        seq_len = src_ids.size(1)
        embed = self.embedding(src_ids) * math.sqrt(self.d_model)
        embed = embed + self.pos_encoder[:, :seq_len, :]
        out = self.encoder(embed)
        logits = self.fc_out(out)
        return logits
```

And the training loss is computed as:

```python
# Line 215 of download_and_train_large_dataset.py
logits = model(src_tensors)
loss = criterion(logits.view(-1, VOCAB_SIZE), tgt_tensors.view(-1))
```

#### Why This Cannot Perform Machine Translation:
1. **No Target Autoregression:** There is no decoder to condition each generated token on previously generated target tokens ($P(y_t \mid y_{<t}, x)$).
2. **Strict 1-to-1 Positional Assumption:** By computing cross-entropy between `logits[:, i, :]` and `tgt_tensors[:, i]`, the model is forced to predict target token $i$ directly from source token $i$.
3. **Word Order and Length Invariance:** Hindi and Santali have different word orders and differing token lengths. In this model, if the source has 4 words and the target has 6 words, positions 5 and 6 cannot be produced at inference time because the output sequence length is strictly tied to the input sequence length (`seq_len = src_ids.size(1)`).
4. **Inference Failure:** During ONNX inference ([`OnnxTranslationEngine.kt:107-124`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/app/src/main/java/com/alchemists/tribetalk/translation/OnnxTranslationEngine.kt#L107-L124)), the Android engine takes the argmax at each input token position:
   ```kotlin
   // OnnxTranslationEngine.kt line 109
   val resultTokens = LongArray(firstBatch.size)
   for (i in firstBatch.indices) { ... resultTokens[i] = maxIdx.toLong() }
   ```
   This means translating a 3-word Hindi sentence will always yield exactly 3 Santali tokens, regardless of actual grammatical requirements.

## 11. Current Risks

1. **Linguistic Credibility Risk in Demonstrations:**  
   If the synthetic pairs in `hindi_santali_large_parallel.csv` or similar template expansions are ever presented to native Santali speakers, linguists, or SIH jury evaluators, sentences like *"तुम किताब पढ़ता हूँ"* / *"ᱟᱢ ᱯᱩᱛᱷᱤᱧ ᱯᱟᱲᱦᱟᱣ ᱠᱟᱱᱟ"* and *"वे दौड़ता हूँ"* / *"ᱩᱱᱠᱩ ᱤᱧ ᱫᱟᱹᱲ ᱮᱫᱟ"* will be immediately flagged as ungrammatical.
2. **Architectural Hallucination in Training Code:**  
   Anyone attempting to retrain `download_and_train_large_dataset.py` on a larger corpus will find that the model cannot translate sentences of differing lengths, producing degraded outputs due to the encoder-only sequence labeling architecture.
3. **Severe Mobile Memory Exhaustion:**  
   Attempting to deploy the 320M IndicTrans2 model directly into Android without aggressive pruning or a truly compact Seq2Seq base (e.g., a fine-tuned 50M–100M parameter model or quantized NLLB distilled variant) will cause Android OS low-memory-killer (LMK) aborts on target 2 GB devices.
4. **Silent Failure / Mock Reporting in Mobile App:**  
   In [`NeuralNMTTranslationEngine.kt:108-116`](file:///c:/Users/keshv/OneDrive/Desktop/tribetalk/TribeTalk/app/src/main/java/com/alchemists/tribetalk/translation/NeuralNMTTranslationEngine.kt#L108-L116), when ONNX model inference is unavailable, the fallback dictionary lookup tags the result as `engineTier = "ONNX_EDGE_AI"` and `confidence = "High (Edge AI Neural • 0ms)"`. Presenting a hardcoded dictionary hit as a neural translation is misleading.
5. **Orthographic Drift from Missing Ohod:**  
   If V2 training data continues using ASCII hyphens instead of Ol Chiki Ohod (`ᱼ`), any trained model will produce non-standard Ol Chiki spelling that will be rejected by official JCERT textbooks and fail evaluation against standard benchmarks.

## 12. Recommended Dataset Requirements for V2

To build a production-ready, domain-adapted Hindi $\leftrightarrow$ Santali NMT model for TribeTalk V2, the dataset must satisfy the following criteria:

### 1. Volume & Split Recommendations
* **Domain-Specific FLN & Primary Curriculum Set:** 3,000–5,000 verified sentence pairs covering JCERT MTB-MLE readers (Grades 1–5), classroom instructions, mathematics, environmental studies, and basic conversational exchanges.
* **Open-Domain / Conversational Background Set:** 30,000–50,000 high-quality parallel sentence pairs filtered from verified subsets of AI4Bharat BPCC and Meta FLORES-200 to provide general linguistic coverage.
* **Strict Splitting Protocol:**
  * **Train Set:** 80%
  * **Validation Set:** 10% (strictly disjoint sentences; no template overlap)
  * **Test Benchmark Set:** 10% (held-out gold-standard verified by native Santali linguists)

### 2. Linguistic & Orthographic Standards
* **Mandatory Ohod Normalization:** All verb suffixes and checked consonant releases must use the official Unicode Ol Chiki Ohod (`ᱼ` U+1C7E). ASCII hyphens must be systematically replaced or purged.
* **Full Punctuation Consistency:** Every sentence pair must have standardized terminal punctuation: Hindi purna viram (`।`) mapped to Santali mucạd (`᱾`), and question marks (`?`) maintained consistently across both sides.
* **Grammatical Inflection Protocol:** Never use naive string concatenation for synthetic data expansion. If data augmentation is performed, it must use rule-based morphological paradigms that correctly inflect both the Hindi verb (*पढ़ता हूँ*, *पढ़ते हो*, *पढ़ता है*, *पढ़ते हैं*) and the Santali pronominal clitics (*-ᱧ*, *-ᱢ*, *-ᱭ*, *-ᱞᱤᱧ*, *-ᱵᱤᱱ*, *-ᱠᱤᱱ*, *-ᱞᱮ*, *-ᱵᱚᱱ*, *-ᱯᱮ*, *-ᱠᱚ*).

### 3. Verification Protocol
* Every FLN curriculum sentence pair must be validated by at least two native Santali speakers literate in Ol Chiki.
* Zero synthetic string-concatenation data should be admitted into the gold benchmark set.

4. **Vocabulary Strategy:**  
   Will the model use the unified 256k NLLB SentencePiece vocabulary, the 122k IndicTrans2 vocabulary, or a custom pruned bilingual 16k–32k SentencePiece model trained exclusively on Hindi and Ol Chiki Santali?

7. **Offline vs. Hybrid Model Splitting:**  
   Should large-scale open-domain neural translation be delegated to a local LAN school-server microservice (FastAPI on teacher laptop / Raspberry Pi), while the Android tablet runs a lightweight 50M model or dictionary engine for instant offline classroom prompts?
8. **Evaluation Metric Target:**  
   What is the target threshold for V2 domain adaptation? (e.g., `chrF++ > 48.0` on primary classroom test set, `latency < 1,500 ms` on mobile ARM CPU).
9. **Tokenizer Synchronization:**  
   How will the tokenization pipeline be unified between Python export and Android runtime to ensure token IDs match 100% across platforms?
10. **Data Licensing:**  
    Are all proposed external training sources (BPCC, FLORES-200, JCERT readers) licensed for integration into the SIH deployment artifact?
